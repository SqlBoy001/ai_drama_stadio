# AI漫剧平台：交付规划与进度总表

更新：2026-09-21。此文件是面向用户的当前状态入口；历史过程与日志在[progress.md](progress.md)，执行接续在[../task_plan.md](../task_plan.md)。每完成一个子问题，同步状态、证据、阻塞和下一步，不以“代码已写”代替验收通过。

## 交付目标

用户输入大概方向，经必要引导得到故事方案；平台规划角色、分镜和素材，独立审核并最多修正两轮，失败转人工；最后通过可编辑时间线制作视频，审核后交付。目标样片约120秒、720p，动作连贯、对白清晰、有爽点/伏笔。生成内容有不确定性，不承诺零错误或必然爆款。

首版范围：单机、单用户、带审核节点的短剧制作。多人协作、账号计费、批量无人值守、多租户、自动发布暂不纳入首版。用户不需要学习提示词或工具参数，但保留创作选择与人工接管。

## 推进顺序与停留条件

1. **M1：后期样片完整。** B3→B4；先复用现有素材补齐字幕/浮层、复审。不需要新增生成预算。发现旧素材本身不合格，明确标记；剪辑不能修复的问题回生成阶段。
2. **M2：平台真正接通。** C1→C2→C3，C4补齐剪辑计划。先Mock/隔离数据库验证，再用真实批准素材验证。当前Desktop工具实测成功不等于后台服务能直接调用，须核实实际适配方式后实现，不能猜端口或虚构API。
3. **M3：可靠性与作品质量。** D1；D2先小样再全片，质量不通过不扩量；费用上限和失败处理先记录。过去60/30元制作预算不复用。
4. **M4：用户验收与交付。** D3→E1。用户验收前由Agent完成开发自测、QA问题修复和产品体验复核，提供作品、报告、限制和可复现步骤。

阶段不按日历强行推进。具体工期在M1确认内容缺陷、M2确认适配能力后更新，不用未经验证的估时制造已承诺交期。

## 验收职责与执行约束

- Agent负责：规划、实现、启动/语法/构建/单测/冒烟、页面检查、素材与成片复审、定位修复、更新本表。每次只解决一个可验证子问题。
- 用户介入：必须本人完成的登录/授权、超既定范围的新付费预算、两轮仍不通过的创作判断、最终业务验收。已有授权不重复询问。
- 内容审查建议标准：关键角色和动作归属不串位；字幕与台词无重大错配；无遮挡关键信息、破音或明显音轨重叠；首段尽快建立冲突，结尾保留明确追更问题。关注度需要实际发布数据验证，不作为软件可以保证的结果。
- 本表记录的是任务状态，不是后台定时任务；每次执行开始/模块结束同步更新。跨任务先读本表与最新日志，避免沿用旧的安装阻塞状态。
